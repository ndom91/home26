How the Standard.site publishing path works

Explainer for the new AT Protocol publishing scaffold in home26.

TL;DR

The repo remains the source of truth. A local script reads MDX posts, creates AT Protocol site.standard.* records on your PDS, writes returned document URIs back into frontmatter, and the website exposes those URIs for Standard.site verification.

File Tour

scripts/publish-standard-site.ts

The local publisher. Reads posts, validates portable MDX, upserts ATProto records, uploads small cover blobs, and writes returned URIs back into repo files.

content-collections.ts

Adds optional standardSiteUri to the typed post model, separate from discussionAtprotoUri for Bluesky comments.

src/routes/blog.$slug.tsx

Emits <link rel="site.standard.document" href="at://..."> on blog posts that have a Standard.site document URI.

src/routes/[.]well-known.site[.]standard[.]publication.ts

Serves the publication AT-URI as plain text at /.well-known/site.standard.publication.

src/lib/standard-site.generated.ts

Committed generated config. Starts empty, then stores the publication AT-URI after the first real publish.

src/routeTree.gen.ts

Generated TanStack route tree. Important because the hidden folder version was ignored; escaped-dot filename is now registered.

Dry Run

Checks the full publishing path without credentials or network writes. Because current covers are too large, this needs the explicit omission flag.

pnpm atproto:publish --dry-run --omit-oversized-covers

Publish One Post

Use this first when testing against the real PDS. It will create/update the publication if needed, then one document record.

ATP_IDENTIFIER=ndo.dev ATP_PASSWORD=... pnpm atproto:publish --post link-screenshot --omit-oversized-covers

Publish Everything

After the single-post test looks right, omit --post to publish all non-draft posts.

ATP_IDENTIFIER=ndo.dev ATP_PASSWORD=... pnpm atproto:publish --omit-oversized-covers

Verify Site Build

Run this after the script writes standardSiteUri fields and the generated publication URI.

pnpm typecheck
pnpm lint
pnpm build

What To Watch

Remaining decisions and failure modes.
Thing Why it matters Current behavior
Rich Markdown content The exact Leafpub-compatible content union type is still unknown. Publisher sends metadata and textContent, not rich structured Markdown.
Oversized covers ATProto blobs cap at 1 MB; current cover images are larger. Fails unless you pass --omit-oversized-covers or compress covers.
Missing publication URI Standard.site needs the well-known endpoint to point at a publication record. Route returns 500 until the generated URI is populated.
MDX portability Live MDX components do not have a Standard.site representation yet. Script rejects posts with live imports/JSX outside code fences.
Why keep discussionAtprotoUri?

discussionAtprotoUri is for Bluesky discussion threads. standardSiteUri is for the Standard.site document record. They are different records with different jobs.

Why stable rkeys?

Stable rkeys make first-time publishing idempotent. A post slug maps to the same at://.../site.standard.document/{slug} URI even if frontmatter is missing.

Why escaped route filename?

TanStack ignored the hidden .well-known directory. The escaped filename keeps the literal URL path while making the route generator include it.

Mental Model

Think of this as a bridge, not a migration. Your website and Git repo still own the article source and rendering. AT Protocol gets a discoverable mirror record for each post. Standard.site verifies that the website and the AT records point at each other: the publication endpoint points from ndo.dev to the publication record, and each blog page points to its document record.
